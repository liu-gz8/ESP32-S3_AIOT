## 4. 关键硬件事实(来自 IDMP441/INMP441 数据手册)

1. INMP441 是 **I²S 标准接口(Philips)**,不是 PDM;
2. 每声道 **24bit 数据、占 32bit 槽位**,每个 WS 帧固定 **64 个 BCLK**;
3. WS 频率 = 采样率,范围约 7.8k~50kHz;
4. 供电 1.62~3.63V,**必须用 3.3V,不能接 5V**;
5. `L/R` 引脚:接 GND → 左声道输出;接 VDD → 右声道输出;
6. SD 三态输出,建议 SD 线带 100kΩ 下拉(模块一般已内置);
7. 上电后前约 85ms 输出全零,是正常启动过程。

## 5. 遇到的问题与排查方法(重要存档)

### 5.1 PDM 配置下数据恒定 -30935

- **现象**:PDM RX 例程下,采样值清一色 -30935,说话无变化;
- **关键线索**:官方 PDM 示例 README 明确写过"未接麦克风时输出 -30935",说明输入信号是"静止/悬空"的;
- **排查步骤**:
  1. 确认程序在读、没崩 —— 说明 DMA/软件链路活着,问题在信号侧;
  2. 人为短接/触碰 DATA 引脚,看数值是否变化;
  3. 核对引脚定义与实际接线;
  4. 检查供电/共地、SEL/L-R 引脚状态;
- **根因**:INMP441 是 **I2S 标准接口芯片**,用 PDM 接收模式根本对不上,自然收不到真实数据。
- **教训**:先看芯片数据手册确认接口类型,再选外设模式。

### 5.2 官方 I2S 回环例程数据正常,但只是固定码型

- **现象**:改为官方 STD 例程后能持续收到数据,内容是 `12 34 56 78 ...` 固定码型;
- **结论**:这只是验证了"I2S 通路本身能收发"(TX→RX 回环),**不代表麦克风数据正确**;
- **区分方法**:回环码型是周期固定的;真实麦克风数据应随声音变化、静音时是噪声。

### 5.3 include 路径问题(找不到头文件)

- **现象**:`src/main.c` 里 `#include "mic_inmp441.h"`,但头文件在 `src/mic/` 下,编译报 `No such file or directory`;
- **规则**:`#include "x.h"` 的查找顺序是:当前文件所在目录 → 全局 include 目录(本项目含根目录 `include/`)→ **不会自动搜子目录**;
- **解决**:把公共头文件放到 `include/`(最终采用),或写相对路径 `"mic/mic_inmp441.h"`。

### 5.4 头文件不"自治"

- **现象**:`board_config.h` 使用 `GPIO_NUM_x` 却没有包含定义它的头,能否编译取决于 include 顺序;
- **规则**:头文件要用什么就 include 什么,单独被包含也要能编译;
- **修法**:`board_config.h` 加 `#include "soc/gpio_num.h"`,所有头文件加 `#pragma once`。

### 5.5 重复定义官方类型 `i2s_chan_config_t`

- **现象**:头文件里自己 typedef 了 `i2s_chan_config_t`,与 ESP-IDF 冲突,且字段与安装版本不一致(`dma_burst_size` 等不存在);
- **规则**:驱动框架已有的类型不要重定义;以本机安装的 IDF 头文件为准(路径 `...\framework-espidf\components\esp_driver_i2s\include\driver\`);
- **修法**:删除自定义结构体,直接用 `I2S_CHANNEL_DEFAULT_CONFIG(...)` + 官方类型。

### 5.6 `static` 函数/变量跨文件使用

- **现象**:头文件里把函数和通道句柄声明成 `static`,main.c 无法调用;
- **规则**:`static` = 仅本文件可见。对外接口在头文件里做非 static 声明,句柄等私有状态放 .c 内部并加 static。

### 5.7 `i2s_new_channel` 参数顺序

- 官方签名:`i2s_new_channel(config, &tx_handle, &rx_handle)`;
- 只建 RX 必须写:`i2s_new_channel(&cfg, NULL, &rx_chan)`;
- 曾经把 RX 句柄填到 TX 参数位,方向反了。

### 5.8 采样数据解码 / 字节与帧换算

- 32bit 槽位立体声下,DMA 缓冲是交织 int32:`L0 R0 L1 R1 ...`;
- INMP441 的 24bit 有效数据在 32bit 槽内**高位左对齐**,解码:24bit 样本 = `raw >> 8`,转 16bit PCM = `raw >> 16`;
- 常见坑:2048 **字节** = 512 个 int32 = 256 个立体声帧,不是 2048 帧;
- 对齐是否正确的验证:看低位字节是否接近 0、安静/弹麦量级是否合理、左右声道是否随 L/R 接线互换。

## 6. 功能正确性的验证方法(阶段 A 验收标准)

1. **配置合规**:Philips、32bit 槽位、stereo;若 16kHz,BCLK 应为 1.024MHz(64×16k);
2. **静音基线**:解码值在 0 附近小幅波动、有正有负,不恒 0、不顶满幅;
3. **量级参考**:94dB SPL 时峰值约 420,000;音量每降 20dB 数值约降 10 倍(安静时几百~几千,说话几万,弹麦可超十万);
4. **声道隔离**:只弹麦 1 → 仅 L 明显变大;只弹麦 2 → 仅 R 明显变大;对调 L/R 接线后左右应互换;
5. **数据可信**:正常说话不频繁削顶,数值随距离/响度单调变化。
