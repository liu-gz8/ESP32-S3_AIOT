# ESP32-S3 AIoT 项目架构总览

> 本文是项目的"总地图":目标形态、当前进度、分层结构、模块清单、数据流、资源规划与里程碑。
> 更新于 2026-09-12。

## 1. 项目目标

面向低功耗场景的 **语音 + 视觉双模 AI 终端**:

1. **语音唤醒**(常开低功耗监听)→ 唤醒后识别命令词或抓取语音片段;
2. **人脸识别**(按需开启摄像头)→ 身份确认;
3. **识别结果按需上云**(MQTT + JSON,发完即断,不长期联网);
4. **电池供电** + 电量检测,低电量自动关机;
5. 硬件形态:自绘 ESP32-S3 N16R8 板卡(硬件 v2),含双麦克风、功放、OV2640、2 寸 SPI TFT。

└───────────────────────────┬──────────────────────────────────┘

┌───────────────────────────┴──────────────────────────────────┐

## 4. 模块清单(现状)

| 模块 | 文件 | 职责 | 对外接口 |
|---|---|---|---|
| 板级配置 | `include/board_config.h` | 引脚定义 | 宏 |
| 麦克风驱动 | `include/mic_inmp441.h`、`src/mic/mic_inmp441.c` | I2S RX 初始化、读原始帧 | `mic_init()`、`mic_read_frame()` |
| 解码/RMS | `include/audio_format.h`、`src/app/audio_format.c` | 32bit→16bit、分声道 RMS | `audio_convert_to_s16()`、`audio_rms()` |
| VAD | `include/vad.h`、`src/app/vad.c` | 自适应噪声底 + 双门限状态机 | `vad_init()`、`vad_process()` |
| 片段缓冲 | `include/audio_segment.h`、`src/app/audio_segment.c` | pre-roll、片段池、生产/消费队列 | `audio_segment_init/feed/retrieve/release/stats()` |
| 音频输出(规划) | `include/audio_out.h`、`src/app/audio_out.c` | I2S TX 播放、提示音、功放使能 | `audio_out_init/play/tone/play_file/set_enable()` |
| 应用任务 | `include/audio_app.h`、`src/app/audio_app.c` | 采集→解码→RMS→VAD→片段；消费者打印 | `audio_app_task()`、`seg_consumer_task()` |
| 入口 | `src/main.c` | 初始化 + 创建任务 | `app_main()` |

### 关键常量

| 常量 | 值 | 含义 |
|---|---|---|
| `MIC_SAMPLE_RATE_HZ` | 16000 | 采样率 |
| `RX_FRAME_COUNT` | 256 | 每块 256 采样帧 = 16ms |
| `RX_BYTES_PER_FRAME` | 8 | 每帧 L+R 两个 int32 |
| `RX_BUFFER_BYTES` | 2048 | 每块原始字节数 |
| `RX_PCM_BUFFER_BYTES` | 1024 | 每块解码后 int16 字节数 |
| VAD | 门限 8dB、起始 3 帧、结束 18 帧、α=0.96 | 见 `vad.h` |
| 片段 | 16kHz、最长 5s、池 3 个 | 480KB PSRAM + 9.6KB SRAM |

## 5. 数据流

### 5.1 音频链路(已实现)

```
双 INMP441 ──I2S(32bit 槽位, 立体声)──▶ mic_read_frame()
   ──▶ audio_convert_to_s16()  16bit 交织
   ──▶ audio_rms()  左右 RMS
   ──▶ vad_process()  START/END 事件
   ──▶ audio_segment_feed()  pre-roll + 下混 + 片段池
   ──▶ ready_q ──▶ 消费者(retrieve/release)
```

### 5.2 双模链路(规划)

```
             ┌── 连续 16k 单声道 ──▶ ESP-SR(AFE+WakeNet) ──▶ 唤醒事件
音频链路 ────┤
             └── VAD + audio_segment ──▶ 命令片段
唤醒事件 ──▶ 状态机 ──▶ 开摄像头 ──▶ 人脸检测/识别 ──▶ 身份结果
身份结果 + 电量 ──▶ JSON ──▶ 开 WiFi ──▶ MQTT publish ──▶ 断开 ──▶ 待机
```

### 5.3 上报链路(设计完成)

- Topic:`aiot/v1/{device_id}/event`、`.../battery`;
- 只发布不订阅(无下行指令);QoS1;失败入本地队列指数退避;
- JSON 公共字段:`dev / seq / ts / fw / type`;
- 详见 `docs/MQTT上报设计.md`。

### 5.4 播报链路(规划)

```
状态机/事件(唤醒提示、识别结果、低电量告警)
   ──▶ audio_out_play() / audio_out_tone() / audio_out_play_file()
   ──▶ I2S1 TX(16bit)→ DOUT(GPIO12)
   ──▶ 功放(MAX98357A, AMP_EN=38)→ 扬声器
```

关键策略(详见 `docs/音频输出与功放设计.md`):

- 空闲时关断功放(AMP_EN=0);
- **半双工(已确定)**:播放期间暂停 VAD/唤醒并丢弃麦克风数据,播完等待回声衰减后复位 VAD 再恢复;
- 提示音采用**预置文件**(16kHz/16bit/单声道 PCM,存 storage 分区),不依赖网络;
- I2S:与麦克风共用 BCLK/WS(全双工),功放型号 MAX98357A;
- 若未来要做"边播边听",需引入 AEC(播放数据作参考信号)。

## 6. 任务与核心分配

### 现状

| 任务 | 栈 | 优先级 | 说明 |
|---|---|---|---|
| `audio_app_task` | 4096 | 5 | 采集→解码→VAD→片段 |
| `seg_consumer_task` | 4096 | 4 | 取片段并打印(临时消费者) |

### 规划(双核分工)

| 任务 | 核心 | 优先级 | 说明 |
|---|---|---|---|
| 音频采集 + ESP-SR | Core 1 | 高 | 常开,不能被阻塞 |
| 摄像头取帧 + 视觉推理 | Core 0 | 中 | 仅 VERIFY 态运行 |
| MQTT/网络 | Core 0 | 中 | 仅上报时运行 |
| 音频播放(功放) | Core 1 | 中 | 短时任务,与采集需协调(半双工) |
| 电源管理/状态机 | 任一 | 低 | 事件驱动 |

原则:**音频常开与视觉/网络错开核心**,避免互相拖垮。

## 7. 存储与内存规划

### PSRAM(8MB Octal)

| 用途 | 估算 |
|---|---|
| 音频片段池(3 × 5s 单声道) | 480KB ✅已占用 |
| 摄像头帧缓冲(QVGA RGB565 双缓冲) | ≈300KB |
| 模型(ESP-SR + 人脸) | 视模型而定(数百 KB ~ 数 MB) |

### 内部 SRAM

| 用途 | 估算 |
|---|---|
| pre-roll 环形缓冲 | 9.6KB ✅已占用 |
| 各任务栈 | 4KB × N |
| WiFi/MQTT/TLS 运行缓冲 | 40~80KB(连接期间) |

### Flash 分区规划(16MB,支持 OTA)

```csv
nvs,       data, nvs,     0x9000,   0x6000,
otadata,   data, ota,     0xf000,   0x2000,
phy_init,  data, phy,     0x11000,  0x1000,
ota_0,     app,  ota_0,   0x20000,  0x400000,
ota_1,     app,  ota_1,   0x420000, 0x400000,
model,     data, spiffs,  0x820000, 0x400000,
storage,   data, spiffs,  0xc20000, 0x3e0000,
```

现状:工程仍在使用**单应用分区表**,做 OTA 前需要替换。

## 8. 引脚分配(终版,详见 `docs/硬件v2引脚分配表.md`)

| 分支 | 引脚 |
|---|---|
| 音频 | BCLK 10 · WS 11 · DIN 13 · DOUT 12(功放) · 功放使能 38 |
| OV2640 | D0~D7 = 1,2,4,5,6,7,8,9 · PCLK 14 · XCLK 15 · VSYNC 16 · HREF 17 · SIOD 18 · SIOC 21 |
| 摄像头电源 | 43(MOSFET) |
| TFT(SPI) | SCK 39 · MOSI 40 · CS 41 · DC 42 · 背光 PWM 44 |
| 交互 | 状态灯 47 · 按键 0(BOOT 键复用) |
| 备用 | 48 |
| 日志/调试 | USB-CDC + USB-JTAG(19/20) |

不可用:26~32(Flash/PSRAM)、33~37(八线 PSRAM)、19/20(USB)、0/3/45/46(strapping)、22~25(不存在)。

## 9. 电源与低功耗策略

1. **语音常开,视觉/网络按需**:摄像头由 43 控制 MOSFET 断电;WiFi 仅上报时开;
2. **充电管理带 Power Path**(BQ2407x 类),配 Buck-Boost 出 3.3V;
3. **MAX17048 电量计**(I2C 0x36,复用 18/21),轮询读取;
4. **48 = POWER_HOLD**:低电量自动断电,按键唤醒;
5. 背光(44)可 PWM 调光/关闭;功放由 38 控制。

## 12. 待决策与风险

| # | 事项 | 影响 |
|---|---|---|
| 1 | 云平台与 broker 地址、TLS 证书 | 上报联调最后一步 |
| 2 | 人脸识别模型选型(检测/特征) | PSRAM/Flash 占用与准确率 |
| 3 | 唤醒词与命令词表 | 模型体积与识别率 |
| 4 | 硬件 v2 原理图设计 | 决定后续所有实测 |
| 5 | 电池容量与续航目标 | 电源器件选型 |
| 6 | **功放是否需要独立 BCLK/WS** | 若独立,需要额外 2 个 GPIO(当前引脚已满) |
| 7 | 是否接受半双工播放(是否需要 AEC) | 决定能否"边播边听" |

主要风险:双核资源竞争、PSRAM 带宽、模型量化掉点、原型接线噪声(已确认等硬件 v2)、引脚余量仅 1 个。
