# VAD(语音活动检测)设计与验收

> 阶段目标:让设备自己判断"有没有人在说话",输出语音开始/结束事件,为后续识别提供语音片段。
> 本设计从两个麦克风(16kHz、立体声、16bit PCM、每块 256 帧)的数据流出发。

## 1. 范围与目标

- 输入:16bit PCM 立体声帧,每帧含左/右两个样本;
- 处理块:256 帧(16ms @16kHz),与现有采集块一致;
- 输出:三种事件/状态 —— `静音`、`语音开始`、`语音结束`;
- 不做的事:不做识别、不做降噪、不引入模型(这些留给后续阶段)。

## 2. 处理流程

```
每 16ms 一块 PCM
   ↓
1) 计算左右声道能量(RMS 已实现)
   ↓
2) 转 dB: db = 20 * log10(rms + 1)
   ↓
3) 双麦策略:取两声道较大的 db(后续可换成信噪比选路)
   ↓
4) 与"噪声底 + 门限"比较,得到 高于/低于 阈值的布尔量
   ↓
5) 状态机(带起始确认、结束延迟)
   ↓
6) 输出事件:VOICE_START / VOICE_END,并累计时长
```

## 3. 状态机设计

```
       连续 ONSET_N 块超阈值              连续 OFFSET_N 块低于阈值
SILENCE ────────────────────→ SPEAKING ────────────────────→ SILENCE
   ↑                                │
   └──── 连续块时长 < MIN_SPEECH ───┘(过短视为噪声,丢弃,不报事件)
```

规则:

- 起始确认 `ONSET_N`:连续 N 块超阈值才判定"语音开始",用于过滤敲击等瞬时噪声;
- 结束延迟 `OFFSET_N`:连续 M 块低于阈值才判定"语音结束",避免把句子切成碎片;
- 最短语音时长 `MIN_SPEECH_FRAMES`:太短的片段不报事件;
- 最长语音时长 `MAX_SPEECH_FRAMES`:超时强制结束,防止环境噪声导致永不结束。

## 4. 参数表(初始值,实测后调)

| 参数 | 初始值 | 含义 |
|---|---|---|
| `VAD_THRESHOLD_DB` | 8 | 高于噪声底多少 dB 判为语音 |
| `VAD_ONSET_FRAMES` | 3 | 起始确认帧数(≈48ms) |
| `VAD_OFFSET_FRAMES` | 18 | 结束确认帧数(≈288ms) |
| `VAD_NOISE_ALPHA` | 0.95 | 噪声底 EMA 系数(越大越稳、越迟钝) |
| `VAD_MIN_SPEECH_FRAMES` | 6 | 最短语音(≈96ms) |
| `VAD_MAX_SPEECH_FRAMES` | 1875 | 最长语音(≈30s) |
| `VAD_NOISE_FLOOR_INIT_DB` | 30 | 上电初始噪声底(需按实测环境调整) |

说明:阈值用 dB 而不是绝对值,是为了不受音量整体大小影响;噪声底用 EMA 更新,使设备能适应不同房间。

## 5. 接口设计

```c
/* vad.h */
typedef enum {
    VAD_STATE_SILENCE = 0,
    VAD_STATE_SPEAKING,
} vad_state_t;

typedef enum {
    VAD_EVENT_NONE = 0,
    VAD_EVENT_SPEECH_START,
    VAD_EVENT_SPEECH_END,
} vad_event_t;

typedef struct {
    float noise_floor_db;   /* 自适应噪声底 */
    vad_state_t state;
    uint32_t hit_cnt;       /* 连续超阈值块数 */
    uint32_t low_cnt;       /* 连续低于阈值块数 */
    uint32_t speech_frames; /* 语音段长度 */
} vad_t;

void vad_init(vad_t *vad);

/* 每块调用一次;返回本块触发的事件(可能为 NONE) */
vad_event_t vad_process(vad_t *vad, float rms_l, float rms_r);
```

调用位置:在 `audio_app_task` 里,拿到 `audio_rms()` 的结果后调用 `vad_process()`。

## 6. 双麦策略(第一阶段)

- 先用简单方案:`db = max(db_l, db_r)`;
- 后续可升级为"信噪比选路":分别估计两路的噪声底,选择 SNR 更高的一路;
- 再进一步可做双麦时延估计/简单波束形成(属于加分项,不在本阶段范围)。

## 7. 验收指标与测试方法

### 测试素材

录 60 秒音频,覆盖四类片段,并人工标注真实语音区间:

1. 完全安静(10s);
2. 正常说话(20s,含停顿);
3. 敲击/拍手等瞬时噪声(10s);
4. 持续背景噪声(风扇/空调)(20s)。

### 指标

| 指标 | 定义 | 目标(第一版) |
|---|---|---|
| 误触发率 | 静音/噪声段被判为语音的比例 | < 10% |
| 漏检率 | 真实语音段未被检出的比例 | < 10% |
| 起始延迟 | 说话到 SPEECH_START 的毫秒数 | < 100ms |
| 结束延迟 | 说完到 SPEECH_END 的毫秒数 | 200~400ms |
| 稳定性 | 连续运行 30 分钟无异常/无内存增长 | 通过 |

### 记录方式

- 每次调参后跑同一段素材,把指标记入下表;
- 串口打印格式建议:`[VAD] state=SILENCE db=52.3 floor=44.1 event=NONE`;
- 指标表放在本文档"实测记录"一节,作为项目证据。

### 本次记录说明

测试条件:安静室内,正常说话,未使用标准 60 秒测试素材;日志共 276 条 VAD 输出。

观测数据:

| 项目 | 观测值 |
|---|---|
| 总输出行数 | 276 |
| START 事件(event=1) | 11 次 |
| END 事件(event=2) | 5 次(与 START 不成对) |
| 处于 SPEAK 状态的行数 | 243(占 88%) |
| 噪声底 floor | 恒为 38.4,全过程未变化 |
| db 范围 | 27.9 ~ 63.9 |
| 门限值(floor + 10) | 48.4 |

结论(本版本不通过验收):

1. **误触发严重**:11 次 START 全部出现在 db 低于门限值(48.4dB)时,说明门限判断或噪声底逻辑与预期不符;
2. **噪声底未自适应**:floor 全程恒定 38.4,EMA 更新未生效;
3. **事件不成对**:START 11 次、END 仅 5 次,状态机在 SPEAK 状态下长时间滞留(88% 的时间);
4. 真实语音峰值在 58~64dB,高于门限;说明"门限数值本身"可用,但"判断与状态机"需要修;
5. 本组日志缺少人工标注的真值,因此漏检率、起止延迟无法计算,需按第 7 节的标准素材重测。

下一步修正项:

- 修噪声底 EMA(确认静音分支真的在执行);
- 用双门限:起始 `floor + VAD_THRESHOLD`,维持 `floor + VAD_THRESHOLD/2`;
- SPEAK 状态下每块无条件累计 `speech_frames`,END 时统一复位;
- 重测时按标准素材分段记录,补齐误触发率/漏检率/起止延迟。

### 修复后验证(第二组日志,验收通过)

测试条件:安静室内正常说一句话,日志共 129 条 VAD 输出。

| 项目 | 观测值 | 结论 |
|---|---|---|
| START 事件 | 1 次(第 16 行,db=44.4,floor=29.6) | 通过:门限 = floor+8 = 37.6,触发时 db 高于门限 |
| END 事件 | 1 次(第 122 行) | 通过:与 START 一一配对 |
| 误触发 | 0 次 | 通过 |
| floor | 29.1 ~ 29.6(静音段缓慢自适应,说话期间冻结) | 通过 |
| db 范围 | 24.6 ~ 48.7 | 合理 |
| 语音段长度 | SPEAK 共 106 块 ≈ 1.7s(其中有效有声 89 块 ≈ 1.42s) | 与"说一句话"相符 |

遗留说明:

- `speech_frames` 当前语义为"SPEAK 状态持续块数"(包含尾部 18 块静音确认),如需表示纯语音时长需另行定义;
- 漏检率与延迟仍需按第 7 节的标准 60 秒素材复测,本组为单句功能验证;
- 若后续在门限附近出现抖动,可增加 dB 一阶平滑后再比较。
