# 项目知识图谱(ESP32-S3 语音+视觉双模终端)

> 用途:复习自查。每个知识点都标了「项目落点」和「自检问题」——
> 能自己答出自检问题,才算真的掌握;答不出来就回去看对应文件。
> 整理时间:2026-09-13

## 0. 一张总图

```
应用层   main.c(启动编排)
           └─ audio_app_task ── 采集→解码→RMS→VAD→片段 ─→ 队列 ─→ seg_consumer_task
           └─ [待写] speech.c ── ESP-SR:AFE + WakeNet10 + MultiNet7
           └─ audio_out ── 提示音播放(半双工)
           └─ storage ── SPIFFS /spiffs
服务层   vad / audio_segment / audio_format / audio_out / storage / [speech]
驱动层   mic_inmp441(I2S 全双工,ESP-IDF i2s_std 驱动)
硬件层   ESP32-S3 N16R8 + 2×INMP441 + MAX98357A + OV2640 + TFT(后两步未做)
构建层   PlatformIO(espidf) + CMake + Kconfig/sdkconfig + 组件管理器 + 分区表
```

## 3. 音频数字信号处理(DSP)

| 知识点 | 项目落点 | 自检问题 |
|---|---|---|

| RMS:平方和取均值再开方;防溢出用 int64 累加 | `audio_rms()` | 为什么累加要用 int64 而不是 int32? |
| dBFS:20·log10(rms+1),与噪声底做差比绝对阈值稳 | `vad_process()` | 为什么用相对阈值(底噪+8dB)而不是绝对阈值? |
| 自适应噪声底:EMA 平滑,α=0.96 | `VAD_NOISE_ALPHA` | α 调大/调小分别有什么后果? |
| 双门限状态机:起始门限 +8dB、保持门限 +4dB,避免抖动 | `VAD_THRESHOLD` | 为什么"开始"和"保持"要用两个不同门限? |
| 起始/结束判定:连续 3 帧超阈值算开始,连续 18 帧低于保持门限算结束 | `VAD_ONSET_FRAME/VAD_OFFSET_FRAME` | 结束帧数为什么远大于起始帧数? |
| 最短/最长语音:6 帧起判、1875 帧(30s)强制结束 | `VAD_MIN/MAX_SPEECH_FRAMES` | 太长不结束会导致什么问题? |
| pre-roll:开始事件之前的 300ms 音频要先存下来 | `audio_segment_init()` 的 `pre_buf` | 没有 pre-roll 会丢什么? |
| 片段池:3×5s 循环复用 + 峰值/截断标记 | `audio_segment` | 池子满了怎么办?`overrun_cnt` 说明什么? |
