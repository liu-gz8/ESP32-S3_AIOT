# 音频片段缓冲设计(VAD 触发 → 完整语音片段)

> 阶段目标:VAD 判定"语音开始/结束"后,把这一整段 16bit PCM 完整保存下来,作为识别(本地 ESP-SR 或上行传输)的输入。
> 关联:`docs/VAD设计与验收.md`、`docs/VAD标准测试方案.md`

## 1. 输入与输出

- **输入**:`audio_app_task` 每 16ms 产出的 int16 立体声 PCM 块(256 帧/块),以及 `vad_process()` 返回的事件;
- **输出**:一个个"完整语音片段",每个片段包含 PCM 数据 + 元信息(序号、时长、峰值、是否被截断);
- **消费者**:后续的识别模块(本地推理或网络上行),本阶段不做识别,只保证片段被完整、可靠地交出去。

### 1.1 数据布局与术语(必须统一)

| 名词 | 含义 | 当前工程中的形态 |
|---|---|---|
| 采样帧(sample frame) | 一个左声道 + 一个右声道 | raw:int32×2 = 8 字节;pcm:int16×2 = 4 字节 |
| 数据块(block) | 每次 `mic_read_frame()` 读到的 256 个采样帧 | 16ms;解码后 int16 数组共 512 个样本 = 1024 字节 |
| `raw` | 未解码的交织数据 | `[L0 R0 L1 R1 ...]`,int32,共 256 帧 |
| `pcm` | 解码后的交织数据 | `[L0 R0 L1 R1 ...]`,int16,共 512 个样本 |

因此 `audio_segment_feed(pcm, frames, ev)` 中的 `frames` 应传 **256(采样帧数)**,而不是 512。

下混示例:

```c
for (size_t i = 0; i < frames; i++) {
    int16_t l = pcm[2 * i];
    int16_t r = pcm[2 * i + 1];
    mono[i] = (int16_t)(((int32_t)l + (int32_t)r) / 2);
}
```

## 3. 关键设计决策

### 3.1 存单声道还是双声道?

- 语音识别通常使用 **16kHz 单声道 16bit**;
- 双声道存储会把内存翻倍,且识别端一般用不到;
- **建议 v1:下混为单声道**(`mono = (l + r) / 2`),元信息里记录原始左右峰值,便于后续排查;
- 若以后要做双麦波束成形,再改为存双声道(接口不变,只改内部)。

为避免以后返工,建议在模块里留一个编译开关:

```c
#define AUDIO_SEGMENT_STEREO 0   /* 0=下混单声道,1=保留双声道交织 */
```

结构体增加 `uint8_t channels;` 字段,消费者据此判断数据布局。

| 模式 | 每块数据量 | 5 秒片段 | 缓冲池 4 个 |
|---|---|---|---|
| 单声道(0) | 512 字节 | 160KB | 640KB |
| 立体声(1) | 1024 字节 | 320KB | 1.28MB |

### 3.2 前置缓冲(pre-roll)

VAD 报 START 时,语音其实已经开始了(启动确认 3 帧 ≈ 48ms,加上麦克风传播),直接从头录会切掉字头。

做法:始终维护一个 300ms 的小环形缓冲(≈19 块),START 时先把这块内容拷进片段开头。

### 3.3 片段最大时长与溢出

- 建议 `MAX_SEGMENT_SECONDS = 5`(识别场景够用,超长多半是噪声误判);
- 超过上限:截断并置 `truncated = true`,同时结束该片段;
- 识别需要的场景可再调大,但内存要重新评估(见第 5 节)。

### 3.4 并发模型(生产者/消费者)

- 生产者:`audio_app_task`(只写);
- 消费者:识别任务(只读),VAD 结束前不会有人读;
- v1 用 **双缓冲 + FreeRTOS 队列** 传递描述符即可,不必上复杂无锁环形缓冲:
  - 缓冲区池:3~4 个片段缓冲;
  - 片段完成后 `xQueueSend` 描述符;池空时丢弃最旧片段并计数(`overrun_cnt`),避免阻塞采集;
  - 消费者处理完调用 `release` 归还缓冲。

## 4. 接口设计(仅供参考)

```c
/* audio_segment.h */

typedef struct {
    int16_t *samples;        /* 单声道 PCM 数据(由模块分配) */
    size_t   sample_count;   /* 样本数 */
    uint32_t seq;            /* 片段序号 */
    uint32_t duration_ms;    /* 时长 */
    int32_t  peak_l;         /* 原始左声道峰值(调试用) */
    int32_t  peak_r;         /* 原始右声道峰值 */
    bool     truncated;      /* 是否因超长被截断 */
} audio_segment_t;

/* 初始化:分配缓冲池(建议放 PSRAM) */
esp_err_t audio_segment_init(uint32_t sample_rate, uint32_t max_seconds, uint8_t pool_count);

/* 每 16ms 调用一次:传入 stereo PCM 与 VAD 事件 */
void audio_segment_feed(const int16_t *pcm_stereo, size_t frames, vad_event_t ev);

/* 消费者:取一个已完成的片段(阻塞等待 timeout) */
esp_err_t audio_segment_retrieve(audio_segment_t *out, TickType_t timeout);

/* 消费者:用完归还 */
void audio_segment_release(audio_segment_t *seg);

/* 统计:丢弃片段数、当前池占用 */
void audio_segment_stats(uint32_t *overrun_cnt, uint32_t *pool_used);
```

## 5. 内存预算(务必先算再做)

单块数据量:256 帧 × 2 声道 × 2 字节 = **1024 字节 / 块**(16ms)。

| 方案 | 5 秒片段 | 缓冲区池(4 个) | 结论 |
|---|---|---|---|
| 立体声 16bit | 5×16000×2×2 = 320KB | 1.28MB | 太大,不适合内部 RAM |
| 单声道 16bit | 5×16000×2 = **160KB** | 640KB | 放 PSRAM 可行 |
| 单声道 3 秒 | 96KB | 384KB | 更保守 |

建议:

- 缓冲池用 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)` 分配在 8MB PSRAM;
- 前置环形缓冲只有 300ms(单声道 ≈9.6KB),可直接放内部 RAM;
- 分配失败要打印明确错误并降级(例如缩短最大时长)。

## 6. 时序(一次完整语音)

```text
SILENCE 段:每块写入 pre-roll 环形缓冲(不产生片段)
   ↓ VAD 事件 START
把 pre-roll 内容拷入片段缓冲,继续追加当前块
   ↓ SPEAK 段:每块下混 mono 后追加
   ↓ VAD 事件 END
标记片段结束 → 计算时长/峰值 → xQueueSend 描述符
   ↓ 消费者取走并处理(本阶段可以只打印信息)
```

要处理的两个边界:

- START 之前没有 pre-roll 数据(刚上电):允许片段不完整,标记即可;
- END 之后紧接新的 START(连续说话):VAD 已用 OFFSET=18 帧做确认,正常不会重叠;若发生,新片段重新开始。

## 7. 验收标准

本阶段不依赖稳定硬件,先做**软件正确性验收**:

| 项目 | 方法 | 目标 |
|---|---|---|
| 片段完整性 | 每段样本数 ≈ 语音时长(±前置 300ms + 尾部 288ms) | 误差 < 50ms |
| 不丢块 | 采集端统计写入块数,与片段样本数核对 | 无缺口 |
| 池管理 | 连续触发 20 段,检查 `overrun_cnt` 与内存 | 无泄漏、无越界 |
| 前置缓冲 | 说一个爆破音("爸、怕"),片段开头不应缺字 | 可听/可看波形判断 |
| 消费者 | `retrieve` 能拿到片段,`release` 后池可复用 | 无死锁 |
| 内存 | 打印 `heap_caps_get_free_size(MALLOC_CAP_SPIRAM)` | 稳定不下降 |

## 8. 实施步骤

1. 新建 `include/audio_segment.h` + `src/app/audio_segment.c`,先实现:
   - `audio_segment_init()`:PSRAM 分配池 + pre-roll 缓冲;
   - `audio_segment_feed()`:pre-roll 维护、START/END 状态处理;
2. 在 `audio_app_task` 中接入:`vad_process()` 之后调用 `audio_segment_feed(pcm, RX_FRAME_COUNT, vad_event)`;
3. 加一个临时消费者任务:循环 `audio_segment_retrieve()`,打印"seq/时长/峰值/是否截断",确认链路通;
4. 做第 7 节的验收(先软件层面,可用串口日志+内存打印);
5. 稳定后把统计信息(片段时长分布、overrun)记录到本文档,作为后续识别阶段的输入依据。

## 9. 与后续识别阶段的接口约定

- 片段统一为 **16kHz / 单声道 / 16bit PCM**,识别模块可直接使用;
- 若走 ESP-SR:把 `audio_segment_t.samples` 按帧喂给 AFE/唤醒词引擎;
- 若走网络上行:片段可直接按 PCM 或 WAV 编码发送,元信息带上 `seq` 便于服务端对齐;
- 片段时长上限、池大小、是否保留双声道,这些参数在识别阶段确定后再固化。
