# 双模 AI 识别架构设计(语音唤醒 + 图像识别)

> 方向确认:以**语音唤醒**作为低功耗入口,唤醒后用**图像(人脸)识别**做身份确认/交互,形成"语音 + 视觉"双模协同。
> 关联文档:`docs/语音识别接入设计.md`(语音路线选型)、`docs/音频片段缓冲设计.md`(音频流与片段)、`docs/VAD设计与验收.md`。

## 1. 目标状态

| 能力 | 说明 |
|---|---|
| 语音唤醒 | 常开低功耗监听,命中唤醒词后进入交互态(ESP-SR WakeNet) |
| 语音命令 | 唤醒后识别固定命令词(ESP-SR MultiNet)或抓取语音片段上行 |
| 图像识别 | 摄像头取帧 → 人脸检测 → 特征提取 → 与人脸库比对(int8 量化模型) |
| 双模融合 | 唤醒触发视觉确认,两者都通过才执行动作(可按需求放宽) |

## 2. 总体架构

```
                      ┌──────────── 语音分支 ────────────┐
 双 INMP441 ─▶ 解码/下混 16k ─▶ ESP-SR(AFE+WakeNet) ─▶ 唤醒事件
                      │                                  │
                      │         VAD + audio_segment ─▶ 命令片段
                      └──────────────────────────────────┘
                                    │ 事件总线 / 状态机
                                    ▼
                    待机 ──唤醒──▶ 视觉确认 ──通过──▶ 执行动作 / 上报
                                    │
                     摄像头 ─▶ 取帧 ─▶ 人脸检测 ─▶ 特征比对(ESP-DL)
```

## 3. 语音分支

- **常开流**:16kHz 单声道 PCM 逐帧喂给 ESP-SR(AFE + WakeNet),负责唤醒;不能喂"片段",否则唤醒词会断裂;
- **命令段**:唤醒命中后,由自研 VAD + `audio_segment` 抓取命令语音片段,供 MultiNet 识别或网络上行;
- **分工原则**:ESP-SR 管唤醒与命令词,自研 VAD 管片段边界,两者不重复计算同一件事。

## 4. 视觉分支

| 环节 | 方案 | 备注 |
|---|---|---|
| 取帧 | DVP 摄像头(OV2640/OV3660 等) | 帧率按需(2~10fps),不必常开 |
| 检测 | ESP-DL/ESP-WHO 人脸检测模型(int8) | 输出人脸框 |
| 对齐/裁剪 | 按检测框裁剪缩放 | 统一到模型输入尺寸(如 112×112) |
| 特征提取 | 人脸特征模型(int8) | 得到特征向量 |
| 比对 | 与人脸库计算余弦距离 + 阈值 | 人脸库存 flash/NVS,支持增删 |

**关键原则:视觉不做常开**。由语音唤醒(或 PIR/按键)触发后开启摄像头,取帧识别完成即关闭,这是低功耗设计的核心。

## 5. 融合与状态机

```
IDLE(常开语音唤醒 + 视觉休眠)
  │ 唤醒词命中
  ▼
VERIFY(开摄像头,人脸检测 + 识别,限时 2~3s)
  │ 通过                    │ 超时/失败
  ▼                        ▼
ACTING(执行命令/上报)    返回 IDLE(记录失败原因)
  │ 超时或动作完成
  ▼
IDLE
```

策略可配置:

- 严格模式:唤醒 + 人脸都通过才执行;
- 宽松模式:唤醒即执行,人脸仅用于记录/统计;
- 隐私模式:人脸特征仅本地存储与比对,不上传。

## 6. 资源预算(ESP32-S3 N16R8)

| 资源 | 现状/规划 | 说明 |
|---|---|---|
| 内部 SRAM | 512KB(系统占用后余量有限) | 任务栈、音频中间缓冲、pre-roll |
| PSRAM | 8MB Octal(已启用) | 音频片段池、模型、摄像头帧缓冲 |
| Flash | 16MB(已配置) | 建议为模型单独分区,便于 OTA |
| 音频片段池 | 480KB(3 × 5s 单声道) | 已实现 |
| 摄像头帧缓冲 | QVGA RGB565 ≈150KB/帧 | 建议双缓冲 ≈300KB |
| 模型 | 依所选模型而定 | 检测 + 特征两套,均 int8 量化 |

**CPU/任务规划建议**:

| 任务 | 核心 | 优先级 | 说明 |
|---|---|---|---|
| 音频采集 + 下混 | Core 1 | 高 | 不能被阻塞 |
| ESP-SR 推理 | Core 1 | 中高 | 与采集同核但错开时序,或独立任务 |
| 摄像头取帧 | Core 0 | 中 | 仅在 VERIFY 态运行 |
| 视觉推理 | Core 0 | 中 | 与取帧交替 |
| 应用状态机/上报 | 任一 | 低 | 事件驱动 |

> 双核分工是必须的:语音常开 + 视觉推理同时跑在一个核上会互相拖垮。

## 7. 硬件 v2 需求(在音频需求基础上增加)

### 7.1 引脚约束(以 ESP32-S3-WROOM-1 / MINI-1 数据手册为准)

| 类别 | GPIO | 说明 |
|---|---|---|
| SPI Flash | 26~32 | 模组内部占用,不可他用 |
| Octal PSRAM(R8) | 33~37 | 八线 PSRAM 占用,不可他用 |
| USB | 19/20 | 原生 USB(JTAG/CDC) |
| 串口控制台 | 43/44 | 默认日志口,可重映射但要谨慎 |
| 启动 strapping | 0/3/45/46 | 上电电平敏感 |
| 不存在引脚 | 22~25 | ESP32-S3 无这些 GPIO |
| 音频(现状) | 10(BCLK)/11(WS)/13(DIN) | 3 根信号线 |
| 摄像头 DVP | 约 12~16 根 | 数据 + PCLK/XCLK/VSYNC/HREF/SCCB |

**建议**:投板前先画完整分配表(音频 + 摄像头 + 屏幕/按键 + 预留 4~6 个 GPIO),避免与 PSRAM/Flash/USB 冲突。

### 7.2 摄像头硬件要点

- 摄像头模块单独供电并在不用时**断电**(MOSFET/负载开关控制),降低待机电流;
- DVP 数据线尽量等长、远离时钟与电源;
- 预留摄像头复位/电源使能控制脚;
- 预留调试接口(串口/测试点)。

### 7.3 交互与状态指示

- 唤醒指示灯(或屏幕提示)与"识别中/通过/失败"状态反馈;
- 至少一个按键(手动触发识别、复位)。

## 8. 里程碑

| # | 里程碑 | 依赖硬件 | 验收 |
|---|---|---|---|
| M1 | 接入 `esp-sr` 依赖,工程编译通过 | 无 | 编译成功,记录固件体积 |
| M2 | AFE + WakeNet 连续喂流 | 稳定麦克风 | 串口输出唤醒事件,无崩溃 |
| M3 | 唤醒率/误唤醒统计 | 稳定麦克风 | 记录唤醒率、5 分钟误唤醒次数 |
| M4 | 摄像头取帧 + 显示/串口验证 | 摄像头硬件 | 稳定 2~10fps,记录内存 |
| M5 | 人脸检测(ESP-DL) | 摄像头硬件 | 检测耗时/内存/准确率 |
| M6 | 人脸识别(特征比对 + 人脸库) | 摄像头硬件 | 通过率/误识率,阈值调整记录 |
| M7 | 双模融合(唤醒 → 视觉确认 → 动作) | 全部 | 端到端演示 + 延迟统计 |
| M8 | 低功耗调度(唤醒触发 + 占空比) | 全部 | 平均电流、单次识别能耗 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 引脚冲突 | 投板返工 | 先做引脚分配表,再画原理图 |
| CPU/PSRAM 竞争 | 卡顿、丢帧 | 双核分工;视觉只在 VERIFY 态运行 |
| 模型量化掉点 | 识别率下降 | 用真实数据评估;必要时调阈值/换模型 |
| 唤醒误触发 | 功耗与体验 | 唤醒阈值调优 + 视觉二次确认 |
| 功耗超预期 | 续航不足 | 摄像头电源门控 + 占空比,实测平均电流 |
| 原型接线噪声 | 数据不可信 | 等硬件 v2 再定标(延续现有结论) |

## 10. 下一步动作

1. **M1**:添加 `esp-sr` 组件依赖并跑通编译(需要联网拉取,单独申请授权);
2. **引脚分配表**:音频 + 摄像头 + 预留,交付给 PCB 设计;
3. 硬件 v2 到位后:VAD 标准素材复测 → M2/M3 → 摄像头 M4/M5;
4. 每完成一个里程碑,更新开发日志并提交。

## 11. 上报链路(已确认)

识别结果与电池电量通过 **MQTT 上报云平台**,采用**按需联网**(有识别结果才连接,发完即断),数据格式为 JSON;不做 U 盘拖拽升级(USB 仅用于烧录/控制台)。

详细设计见 `docs/MQTT上报设计.md`:

- Topic:`aiot/v1/{device_id}/event`(识别结果)、`.../battery`(电量);
- 公共字段:`dev / seq / ts / fw / type`,事件细节放 `event` / `voice` 子对象;
- 失败进本地队列(LittleFS),指数退避重试,服务端按 `dev + seq` 去重;
- 电量计建议 MAX17048(挂摄像头 I2C 总线,不额外占引脚),随事件上报。
