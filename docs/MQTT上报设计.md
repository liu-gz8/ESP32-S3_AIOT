# MQTT 上报设计(识别结果 + 电池电量)

> 场景:语音唤醒 + 图像识别完成后,**按需联网**(不长期在线),通过 MQTT 把 JSON 结果上报云平台。
> 关联:`docs/双模AI识别架构设计.md`、`docs/WiFi上报与USB升级可行性分析.md`、`docs/硬件v2引脚分配表.md`。

## 1. 设计决策(已确认)

| 项 | 决定 |
|---|---|
| 上报内容 | 识别结果(语音/人脸)+ 电池电量 |
| 传输方式 | MQTT over TCP(建议 TLS) |
| 联网策略 | **按需联网**:有识别结果才连接,发完即断 |
| 数据格式 | JSON |
| U 盘拖拽升级 | 不做(USB 仅用于烧录/调试/控制台) |
| 长期在线 | 不需要(不做常驻心跳) |
| 下行指令 | **不需要**(只发布,不订阅) |
| 原始音频/图像 | **不上报**(仅上报识别结果) |
| 云平台 | **待定**:设计保持平台无关,broker 地址/端口/鉴权在 NVS 配置 |
| 电量计 | **MAX17048**(I2C,地址 0x36,复用摄像头 I2C 总线) |

## 2. 单次上报时序

```
唤醒词命中 / 人脸识别完成
        │
        ▼
组装 JSON ──▶ 入队(pending)
        │
        ▼
WiFi 使能 ──▶ 连接 AP(超时 5s,重试 2 次)
        │
        ▼
MQTT 连接(TLS 握手,超时 5s)
        │
        ▼
publish(QoS1) ──▶ 等 PUBACK(超时 3s)
        │
        ├─ 成功 ──▶ 出队, 关闭 MQTT/WiFi, 回待机
        └─ 失败 ──▶ 保留在队列, 下次事件或退避后重试
```

时间预算(WiFi 连接 1~3s + TLS/MQTT 0.5~2s + 发布 <0.1s)≈ **3~6 秒**。
功耗估算:WiFi 平均约 100mA × 5s ≈ 0.14mAh/次,2000mAh 电池可支撑上万次上报,不构成瓶颈。

## 3. Topic 设计

建议统一前缀 `aiot/v1/{device_id}/`,便于云平台做多设备管理。

| Topic | 方向 | QoS | Retain | 用途 |
|---|---|---|---|---|
| `aiot/v1/{device_id}/event` | 设备→云 | 1 | 否 | 识别结果(语音/人脸) |
| `aiot/v1/{device_id}/battery` | 设备→云 | 1 | 可选 | 电池状态(变化较大时单独发) |

说明:

- **只发布、不订阅**(无下行指令),连接后直接 publish,收到 PUBACK 即断开;
- 按需联网模式下,Last Will(离线遗嘱)意义不大,不做常驻在线状态;
- 服务端按 `dev + seq` 去重,因此不需要单独的 ack 主题。

## 4. JSON 格式

### 4.1 公共字段(每次上报都带)

| 字段 | 类型 | 说明 |
|---|---|---|
| `dev` | string | 设备 ID(MAC 或烧录的 SN) |
| `seq` | number | 自增序号,用于去重(断电不清零则存 NVS) |
| `ts` | number | Unix 时间戳(秒);NTP 未同步时为 0,由服务端补齐 |
| `fw` | string | 固件版本 |
| `type` | string | 事件类型:`face` / `voice` / `battery` |
| `battery` | object | 电量信息(见下) |

### 4.2 示例:一次"语音唤醒 + 人脸通过"

```json
{
  "dev": "esp32s3-a1b2c3",
  "seq": 128,
  "ts": 1757600000,
  "fw": "0.4.0",
  "type": "face",
  "event": {
    "result": "pass",
    "identity": "user_01",
    "confidence": 0.93,
    "latency_ms": 480
  },
  "voice": {
    "wake": "hi_esp",
    "cmd": "turn_on_light",
    "score": 0.88
  },
  "battery": {
    "percent": 76,
    "voltage_mv": 3912,
    "charging": false
  },
  "net": {
    "rssi": -58
  }
}
```

### 4.3 示例:仅电量上报

```json
{
  "dev": "esp32s3-a1b2c3",
  "seq": 129,
  "ts": 1757603600,
  "fw": "0.4.0",
  "type": "battery",
  "battery": { "percent": 74, "voltage_mv": 3901, "charging": false }
}
```

字段设计原则:

- **必需字段尽量少**(dev/seq/ts/type),便于服务端解析与去重;
- 事件细节放子对象(`event` / `voice`),不同类型互不干扰;
- `percent` 来自电量计(建议 MAX17048/BQ27441,挂在摄像头 I2C 总线上,不额外占引脚);
- `charging` 来自充电 IC 状态脚或电量计寄存器。

## 5. 电量上报策略

| 时机 | 动作 |
|---|---|
| 每次识别上报 | 附带当前电量(不额外联网) |
| 电量变化 > 5% 且有识别事件 | 随事件上报 |
| 低电量(<15%) | 立即尝试上报一次并提示用户 |
| 充电状态变化 | 随下一次事件上报 |

不做定时心跳上报(与"不长期联网"的决策一致)。

## 6. 失败处理与离线队列

1. 上报前先落盘(pending 队列),再尝试发送;
2. 失败(连不上 AP / MQTT 超时 / 未收到 PUBACK)→ 保留,按 **指数退避**(5s、15s、60s、5min)重试;
3. 队列存 `storage` 分区(LittleFS),建议上限 200 条,超限**丢最旧**并计数;
4. 去重:服务端按 `dev + seq` 去重;
5. 失败原因记录到日志(仅本地),便于现场排查。

## 7. 安全与配网

| 项 | 方案 |
|---|---|
| 传输 | 云平台确定前保持平台无关:内网/调试可用 1883,正式环境建议 TLS(8883)+ 服务器证书 |
| 设备鉴权 | 一机一密(用户名/密码或 Token),存 NVS |
| 配网 | 首次使用用 BLE 配网或 SmartConfig;WiFi 账号存 NVS |
| 时间 | 首次联网做一次 SNTP 同步;失败时 `ts=0` 由服务端补齐 |
| 隐私 | 人脸特征本地保存比对,仅上报"身份 ID + 置信度",**不上传原始图像/音频** |
| broker 配置 | 地址 / 端口 / 用户名 / 密码(或 Token)/ 是否 TLS,统一存 NVS,便于后续换平台 |

## 8. 资源占用估算

| 项目 | 估算 | 说明 |
|---|---|---|
| MQTT + TLS 缓冲 | 约 40~80KB 堆 | 连接期间占用,断开后释放 |
| JSON 文档 | < 1KB | 固定长度缓冲即可 |
| 离线队列 | 每条 < 1KB × 200 | 放 storage 分区 |
| CPU | 连接与 TLS 握手有开销 | 建议放 Core 0,与视觉推理错峰 |

## 9. 与双模流程的衔接

```
IDLE(语音常开, WiFi 关, 摄像头断电)
  │ 唤醒词命中
  ▼
VERIFY(开摄像头 → 人脸识别)
  │
  ▼
REPORT(组装 JSON → 入队 → 开 WiFi → MQTT → 发布 → 断开)
  │
  ▼
IDLE
```

与音频链路的关系:需要上传"原始语音片段"时,使用 `audio_segment` 产出的片段;本设计默认**只上报识别结果**,不上传原始音频(更省流量与功耗)。
