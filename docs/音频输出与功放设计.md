# 音频输出(功放/播报)设计

> 用途:唤醒提示音、语音反馈/播报、告警(低电量、识别失败)等需要"设备发声"的场景。
> 关联:`docs/项目架构总览.md`、`docs/硬件v2引脚分配表.md`、`docs/双模AI识别架构设计.md`。

## 1. 引脚与硬件(已在引脚表中确定)

| 功能 | GPIO | 说明 |
|---|---|---|
| I2S DOUT | 12 | 主控输出音频数据 |
| 功放使能 AMP_EN | 38 | 控制功放 SD/EN,空闲时关断省电 |

功放模块选型建议:

| 型号 | 类型 | 供电 | 特点 |
|---|---|---|---|
| **MAX98357A(已选定)** | I2S 数字功放 | 2.5~5.5V | 免 MCLK、免耦合电容、单声道、增益由电阻设定 |
| PCM5102A | I2S DAC | 3.3V | 需外接模拟功放,体积大 |
| NS4150/其他模拟功放 | 模拟输入 | 3.3~5V | 需外接 DAC/滤波,不推荐 |

MAX98357A 关键配置(打样前确认):

| 项 | 配置 | 说明 |
|---|---|---|
| I2S 格式 | 标准 I2S(Philips),无需 MCLK | 只需要 BCLK / LRC(WS) / DIN |
| 数据位宽 | 支持 16/24/32bit | **需实测确认接受 64×fs / 32bit 槽位**(见第 3 节) |
| 采样率 | 8~96kHz | 16kHz 播放属其支持范围 |
| GAIN 脚 | 外接电阻设定增益(3/6/9/12/15dB) | 建议留焊盘,按音量需求调 |
| SD_MODE 脚 | 拉低关断;**建议由 GPIO38(AMP_EN)控制**,并保留分压电阻选择左右声道 | 空闲关断省电 |
| 供电 | 3.3V(约 1~1.8W@4Ω)或 5V(约 3W@4Ω) | 5V 更响,需升压轨;3.3V 更省电 |
| 扬声器 | 4Ω / 8Ω | 注意功率匹配,避免失真 |

要点:

- MAX98357A 直接吃 I2S,**不需要 MCLK**,只需 BCLK/WS/DIN;
- 输出功率与供电相关(3.3V 供电约 1~1.8W@4Ω,5V 可达 3W);若要更响,需为功放单独一路升压;
- 增益由 GAIN 脚电阻设定,建议预留焊盘;
- 扬声器 4Ω/8Ω 均可,注意功放与扬声器功率匹配。

## 2. 软件架构

新增模块(建议命名 `audio_out`):

```
include/audio_out.h
src/app/audio_out.c
```

接口约定:

```c
typedef enum {
    AUDIO_OUT_OK = 0,
    AUDIO_OUT_BUSY,      /* 正在播放 */
    AUDIO_OUT_ERROR,
} audio_out_status_t;

/* 初始化 I2S(TX, std 模式)并打开功放使能脚 */
esp_err_t audio_out_init(uint32_t sample_rate);

/* 播放一段 16bit 单声道 PCM(阻塞或按队列执行,二选一) */
esp_err_t audio_out_play(const int16_t *pcm, size_t samples);

/* 播放提示音(内部生成正弦) */
esp_err_t audio_out_tone(uint32_t freq_hz, uint32_t duration_ms);

/* 播放文件(存于 storage 分区的 PCM/WAV 提示音) */
esp_err_t audio_out_play_file(const char *path);

/* 空闲时关断功放,降低静态功耗 */
void audio_out_set_enable(bool on);
```

内部建议:

- 独立播放任务 + 请求队列(可被 VAD/识别任务异步触发);
- 播放期间置位 `busy` 标志,供状态机查询;
- 提示音文件放 `storage` 分区(LittleFS),格式建议 16kHz/16bit 单声道原始 PCM(无需解码器,CPU 占用最低)。

## 3. I2S 资源分配

| 方向 | 控制器 | 引脚 | 说明 |
|---|---|---|---|
| 输入(双麦) | I2S0 | 10(BCLK)/ 11(WS)/ 13(DIN) | 已实现 |
| 输出(功放) | I2S0(**全双工**) | 共享 10(BCLK)/ 11(WS),数据走 12(DOUT) | **推荐方案** |

### 3.1 关键结论:必须共用 BCLK/WS(引脚已无余量)

功放(MAX98357A 类)需要 **BCLK + LRC(WS) + DIN** 三根线。我们目前只分配了 DOUT(12)与 AMP_EN(38),**若让 TX 用独立时钟,需要再占 2 个 GPIO——而引脚表已用满(余量仅 48)。**

因此推荐:**使用同一个 I2S 控制器(I2S0)的全双工模式**,TX 与 RX 共享 BCLK(10)与 WS(11),各自数据线分开(RX=DIN 13,TX=DOUT 12)。总占用仍是 4 根:10 / 11 / 12 / 13。

约束与注意:

1. TX 与 RX 必须使用**相同的采样率与槽位宽度**:当前麦克风链路是 16kHz、32bit 槽位、stereo(BCLK = 64 × fs = 1.024MHz);
2. 因此功放侧要能接受 **64×fs、32bit 槽位的 I2S 数据**。MAX98357A 支持 16/24/32bit I2S,配 64fs 属于 32bit 模式,需在打样前用模块实测确认;
3. 播放数据同样按 32bit 槽位填充(16bit 音频左移对齐或直接给 32bit 样本);
4. 若功放模块**只支持 16bit 且不接受 64fs**,则只能改为"独立时钟",那时需要额外 2 个 GPIO(必须从别的功能里让出)。

### 3.2 备选方案

| 方案 | 引脚 | 代价 |
|---|---|---|
| A. I2S0 全双工共享 BCLK/WS(推荐) | 10/11/12/13 | 需功放接受 64fs/32bit |
| B. TX 独立时钟(I2S1) | 需额外 2 个 GPIO | 当前无余量,必须让出其他功能 |
| C. 分时复用(先采后放) | 同上 | 播放时无法采集,体验受限 |

> 结论:先按方案 A 设计与打样;若实测功放不接受 64fs,再考虑让出引脚走方案 B。

### 3.3 已确定的方案 A 实现要点(待编码)

- 用 `i2s_new_channel()` 在同一控制器创建 **TX + RX 双通道**,两通道使用**相同的 clock 配置**(16kHz);
- RX:32bit 槽位、stereo,数据线 GPIO13(现状);
- TX:同速率、同槽位宽度,数据线 GPIO12,数据按 32bit 槽位填充(16bit 音频左移对齐);
- 播放采样率固定 16kHz(与麦克风一致),提示音文件也按 16kHz 制作,避免重配时钟;
- 打开功放前先使能 TX 通道,关闭顺序相反,避免爆音。

## 4. 回声/自激问题(必须处理)

设备自己播放的声音会被自己的麦克风拾取,可能导致:

- VAD 误判为语音;
- 唤醒词被自己的播报"打断"或误触发。

三种处理策略(按复杂度递增):

| 策略 | 做法 | 代价 |
|---|---|---|
| **半双工(推荐先做)** | 播放期间暂停 VAD/唤醒判断,播放结束再恢复 | 播报时听不到用户说话 |
| 门限抑制 | 播放期间提高 VAD 门限或直接忽略事件 | 简单,但可能导致漏检 |
| **AEC 回声消除** | 用 ESP-SR AFE 的 AEC,需把播放数据作为参考信号喂入 | 可实现边说边听,但集成复杂、占 CPU |

### 4.1 已确定的半双工策略(实现要点)

播放期间的处理顺序:

1. 状态机进入 `PLAYING`,**暂停把音频喂给 ESP-SR / 暂停 VAD 判断**(事件不再上报);
2. 麦克风数据继续读取但**丢弃**(保持 DMA 流转,避免溢出),或直接 `i2s_channel_disable(RX)`;
3. 播放结束 → 等待 **50~100ms 回声衰减**;
4. **复位 VAD 状态**(清零 `hit_cnt/low_cnt/speech_frames`,噪声底可保留)→ 恢复监听;
5. 若第 2 步选择了禁用 RX,需重新使能并确认时钟恢复。

这样可避免"自己的播报触发唤醒/切句"的问题;后续若需要边播边听,再引入 ESP-SR AFE 的 AEC。

## 5. 提示音文件(预置)

已确定采用**预置提示音文件**方案(不做云端 TTS)。

| 项 | 设计 |
|---|---|
| 存储位置 | `storage` 分区(LittleFS) |
| 格式 | **16kHz / 16bit / 单声道 原始 PCM**(免解码,CPU 占用最低);若需人工替换方便,可用 WAV(仅需解析 44 字节头) |
| 采样率一致性 | 与麦克风同为 16kHz,播放时无需重配 I2S 时钟 |
| 文件大小 | 32KB/秒;8 段各 1 秒 ≈ 256KB,storage(约 3.9MB)绰绰有余 |

建议的提示音清单:

| 文件名 | 场景 | 备注 |
|---|---|---|
| `boot.pcm` | 开机就绪 | 可选 |
| `wake.pcm` | 唤醒应答("在呢") | 唤醒后立即播放 |
| `ok.pcm` | 识别通过 | 可与上报同时进行 |
| `fail.pcm` | 未识别/识别失败 | |
| `lowbat.pcm` | 低电量告警 | 优先级最高 |
| `charging.pcm` | 开始充电 | 可选 |
| `error.pcm` | 系统错误 | |

播放优先级建议:`lowbat/error` > `wake` > `ok/fail`,高优先级可打断低优先级(音频队列按优先级排序)。

## 6. 功耗

- 空闲时 `AMP_EN=0` 关断功放(MAX98357A 关断电流约 µA 级);
- 播放时为大电流负载(数百 mA),需与 WiFi 发射、视觉推理错峰;
- 扬声器功率与音量按场景分级(提示音可短、音量适中)。

## 7. 验收标准

| 项 | 方法 | 目标 |
|---|---|---|
| 基本发声 | 播放 1kHz 正弦 1 秒 | 声音清晰、无爆音 |
| 提示音 | 播放"叮"提示音 | 与状态机联动正常 |
| 无自激 | 播放提示音期间观察 VAD/唤醒 | 无错误触发(半双工策略下) |
| 采集不受影响 | 播放前后对比采集丢帧 | 采集无丢帧或按策略暂停 |
| 功耗 | 测量待机与播放电流 | 待机功放关断,电流显著下降 |
| 文件播放 | 播放 storage 中的提示音文件 | 连续播放无卡顿 |
