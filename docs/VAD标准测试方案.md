# VAD 标准测试方案(误触发率 / 漏检率 / 起止延迟)

> 目的:用可复现的测试素材给 VAD 打出量化指标,替代"肉眼看串口"的验证方式。
> 关联文档:`docs/VAD设计与验收.md`

## 1. 指标定义

| 指标 | 定义 | 计算方式 |
|---|---|---|
| 误触发率 | 非语音段(静音/敲击/风扇)被判为语音的程度 | 非语音段中 `state=SPEAK` 的块数 ÷ 非语音段总块数 × 100% |
| 误触发频次 | 非语音段每分钟产生多少次 START | 非语音段 START 次数 ÷ 非语音段时长(min) |
| 漏检率 | 真实语音段中被判为静音的程度 | 语音段中 `state=SILENCE` 的块数 ÷ 语音段总块数 × 100% |
| 起始延迟 | 真实语音起点到 START 事件的时间 | (START 块号 − 语音起点块号) × 16ms |
| 结束延迟 | 真实语音终点到 END 事件的时间 | (END 块号 − 语音终点块号) × 16ms |

判定目标(来自 VAD 设计文档第 7 节):

| 指标 | 目标 |
|---|---|
| 误触发率 | < 10% |
| 漏检率 | < 10% |
| 起始延迟 | < 100ms |
| 结束延迟 | 200 ~ 400ms |

## 2. 前置准备

### 2.1 代码准备(必须)

当前打印缺少"块号",无法定位时间,请先在 `audio_app_task` 的打印里加一个**递增块号**(每读一块 +1),例如:

```c
static uint32_t block_id = 0;
...
block_id++;
printf("blk=%lu state=%d db=%.1f floor=%.1f event=%d frame=%ld\n",
       (unsigned long)block_id, vad->state, vad->voice_db,
       vad->noise_db, vad_event, vad->speech_frames);
```

块号是整个测试的"时间轴":块号 × 16ms = 相对时间。没有它,延迟无法计算。

### 2.2 环境准备

- 设备位置固定,麦克风朝向固定;
- 说话人距离麦克风固定(建议 30~50cm),语速正常;
- 关闭空调/风扇(做风扇测试段时再打开);
- 记录环境描述(房间、距离、噪声源),便于复现。

### 2.3 素材与工具

- 秒表(手机即可)或电脑倒计时提示;
- 风扇一段也可以用手机播放白噪声代替,更可复现;
- 敲击用笔轻敲麦克风 PCB 或桌面。

## 3. 测试脚本(单轮 60 秒)

每一段开始时做一个"标记动作",便于在日志里对齐时间轴。推荐用**一次响亮的拍手**作为分段标记(时长短、峰值明显,日志里能看到突变)。

| 时间段 | 内容 | 真值 | 标记 |
|---|---|---|---|
| 0~15s | 完全安静 | 非语音 | 开始计时即静音 |
| 15~35s | 正常说话(3~4 句,句间自然停顿) | 语音 | 第 15s 拍手一次后开始说话 |
| 35~45s | 敲击(笔敲桌面/PCB,每 1~2s 一次) | 非语音 | 第 35s 拍手一次后开始敲 |
| 45~60s | 持续背景噪声(风扇或白噪声) | 非语音 | 第 45s 拍手一次后开风扇/播放噪声 |

要求:

- 一轮内不要改变距离和音量;
- 共跑 **3 轮**,每轮之间停顿 10 秒以上再开始(让噪声底重新收敛);
- 每轮单独保存日志文件(命名如 `vad_test_1.log`);
- 在第 15s 说第一句话时,尽量让"说"和拍手标记间隔 1~2 秒,便于区分。

## 5. 常见问题与处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 敲击段产生大量 START | 门限偏低 / ONSET 太小 | 提高 VAD_THRESHOLD 或增大 VAD_ONSET_FRAME |
| 语音段被切成多段 | OFFSET 太小 / 句间停顿被当作结束 | 增大 VAD_OFFSET_FRAME |
| 风扇段一直判定为语音 | 噪声底跟不上环境变化 | 检查静音分支 EMA 是否执行;必要时增大 VAD_NOISE_ALPHA 的收敛速度 |
| 说话时判断为静音(漏检) | 门限偏高 / 说话声太小 | 降低门限或增大说话音量;检查麦克风增益/距离 |
| END 迟迟不来 | 维持门限过严(贴边抖动) | 增加 dB 一阶平滑后再比较 |
