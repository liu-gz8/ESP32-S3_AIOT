## 职责划分(本次核心成果)

- **mic 驱动**:只负责 I2S 初始化和读取原始 int32 帧,不依赖解码层;
- **audio_format**:纯数据变换(int32 交织 → int16 PCM、RMS 统计);
- **audio_app**:拥有循环和缓冲,决定"什么时候读、读完做什么";
- **main**:只做初始化和任务创建。

## 今天踩过的坑与排查方法(重点存档)

### 1. 内存崩溃排查

- 现象:读解码循环反复 malloc/calloc 且不 free → 内存泄漏;把字节数当帧数传给解码 → 缓冲区越界;
- 排查工具链:
  - menuconfig 开启 `HEAP_POISONING_COMPREHENSIVE` 与 `HEAP_TASK_TRACKING`;
  - 打印 `heap_caps_get_info()` / `heap_caps_check_integrity_all()`;
  - 崩溃 backtrace 用 `xtensa-esp32s3-elf-addr2line` 反查源文件行号;
- 教训:缓冲区"字节数 / 元素数 / 帧数"三者必须分清;malloc 与 free 必须成对、尽量循环外分配一次。

### 2. 解码正确性

- 交织帧布局 `[L0 R0 L1 R1 ...]`:左声道取 `raw[2*i]`,右声道取 `raw[2*i+1]`;
- 32bit 槽内 24bit 数据左对齐:看 24bit 用 `>>8`,转 16bit PCM 用 `>>16`;
- 2048 字节 = 512 个 int32 = 256 个立体声帧(16ms @16kHz)。

### 3. 读/解码分离时的常见错误

- 错误:把"读"写成无限循环任务,再让 app 去"等"它 → 解码永远不执行;
- 正确:mic 驱动提供"调用一次、返回一块"的函数,由 app 循环调用;
- 跨文件共享裸全局指针(`extern` + malloc 后不管理)是反模式,应改为调用方局部缓冲 + 参数传递。

### 4. 采样率宏

- 定义了 `MIC_SAMPLE_RATE_HZ`,但初始化代码曾仍写死 `16000`;需确认代码使用宏,否则"只改配置不改代码"不成立。
